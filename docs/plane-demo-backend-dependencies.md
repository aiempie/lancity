## 4. Chọn stack cho Lancity

| Phương án                   | Khi phù hợp                                                               | Thành phần đề xuất                                                                                                                                                                         |
| --------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A. Vinext + Workers**     | UI Lancity là bên sử dụng chính và muốn ít dependency                     | Server Actions cho thao tác từ UI. Route Handlers cho webhook và HTTP API. Better Auth + Drizzle + D1 + Zod. Thêm R2/Queues theo tính năng.                                                |
| **B. Hono + Workers**       | Có nhiều API phiên bản, client ngoài, middleware dùng chung hoặc OpenAPI  | Hono cho lớp HTTP API. Có thể thêm `@hono/zod-openapi`. Giữ các service và schema hiện có để UI dùng chung.                                                                                |
| **C. Workers + Live riêng** | Cần nhiều người sửa cùng tài liệu hoặc tái sử dụng pipeline PDF của Plane | Giữ nghiệp vụ trên Workers. Tách **Hocuspocus + Yjs** và pipeline PDF sang Node nếu cần tương thích gần với demo. Đánh giá Hocuspocus v4 trên Workers nếu muốn dùng một nền tảng vận hành. |

Tôi chọn **A** cho phần quản lý workspace/project/issue hiện tại. Chuyển sang **B** khi API cho bên ngoài cần cấu trúc riêng. Đánh giá **C** khi có yêu cầu chỉnh sửa cộng tác hoặc xuất PDF. [Lớp HTTP có sẵn của Next](https://nextjs.org/docs/app/getting-started/route-handlers) · [Hono trên Workers](https://hono.dev/docs/getting-started/cloudflare-workers) · [Hocuspocus server](https://tiptap.dev/docs/hocuspocus/getting-started/overview)
